# Изолированный HTTP-приёмник

Дополнительная цель для тестов на собственном отдельном хосте. Нужен Python 3.11+, сторонних Python-пакетов нет. Сервисы по умолчанию слушают все IPv4-интерфейсы, поэтому заранее ограничьте доступ firewall и выбирайте свободные порты. Не используйте чужой работающий сервис как тестовую цель.

## Журнал запросов

```bash
python3 deploy/target/server.py --port 18081 --log-dir ./target-logs
```

`/load` отдаёт короткий JSON, `/ip` возвращает внешний IP клиента, `/healthz` проверяет доступность. Другие URL дают 404; тела запросов не принимаются. Журнал ограничен тремя файлами по 10 MiB и содержит время, IP клиента, имя endpoint и статус. Заголовки, cookies, query и тела не сохраняются. Лимит одновременных соединений составляет 512; эта версия не собирает отдельный счётчик отказов по лимиту.

## Агрегированные метрики

```bash
python3 deploy/target/peak_server.py --port 18082 --admin-port 18083 --connections 4096 --log ./target-logs/metrics.jsonl
```

Приёмник не пишет строку на каждый запрос. Запросы `/load` группируются по 100-миллисекундным интервалам и идентификатору из `X-Inbound-Lab-Run` (UUID запуска, без секретов). `/ip` служит для проверки туннелей, а не для нагрузочной фазы. Административный endpoint доступен только на `127.0.0.1:18083`, выдаёт JSON со счётчиками принятых запросов, записанных ответов, текущих/максимальных соединений и отказов по лимиту. Входящие запросы с невалидным идентификатором относятся к группе `unknown`.

Пик `peak1s` вычисляется по десяти соседним интервалам с шагом 100 мс. `peak100ms` означает число запросов за 100 мс, а не устойчивый RPS. Принятый запрос не гарантирует, что клиент получил ответ. JSONL сохраняет накопленные снимки; задайте внешнюю ротацию или ограниченную длительность процесса. Для развёртывания на сервере задавайте отдельные лимиты CPU/RAM, пользователя, каталог и время работы службы. Инструмент не настраивает и не перезапускает существующие сервисы.

## Проверки

```bash
python3 -m unittest discover -s deploy/target -p 'test_*.py'
```

Основные клиентские метрики собираются в k6. Эти приёмники нужны только для дополнительной независимой проверки на управляемой вами цели. Перед публикацией логов удаляйте внешние IP и идентификаторы запусков.
