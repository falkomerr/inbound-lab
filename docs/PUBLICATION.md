# Поставка для GitHub

Экспорт создаёт исходное дерево без Git-истории и без личных runtime-данных. Он не создаёт аккаунт или репозиторий, не выполняет commit/push и не меняет работающие развёртывания.

## Что исключено

- Секреты, `.env`, БД, дампы, журналы и отчёты.
- Отчёты о проверках, аудиты, benchmark-результаты и оценки исходного проекта. Код формирования отчётов приложения сохраняется.
- История Git, локальные настройки IDE/агентов, история браузерных проверок.
- Рабочие записи, приватные аудиты, скриншоты прежних тестов и временные результаты.
- `node_modules`, скомпилированные интерфейсы, исходные карты, старый npm lockfile.
- Встроенные upstream-скриншоты и неактуальные вложенные GitHub-настройки FasterTest.

Вместо конкретных SSH-аккаунтов, хостов и путей документация использует локальные или настраиваемые адреса. Имя автора пакета нейтральное. Лицензии и обязательная атрибуция FasterTest сохранены; другие авторы upstream не выдаются за владельца этого развёртывания. Фикстуры VPN используют заведомо синтетический идентификатор. Из JPEG удалены EXIF/XMP/комментарии без изменения пиксельного потока.

## Проверки

Шаблон `.github/ci-template.yml` устанавливает зависимости по `bun.lock`, запускает Python-проверки, скан исходников, Node unit/integration-тесты, lint и обе сборки UI. `bun audit` проверяется отдельно. Унаследованный `.github/workflows/ci.yml` отключён и не адаптирован к структуре Inbound Lab. Перед включением CI замените его шаблоном через учётные данные с правом `workflow`. Сетевые Docker-проверки и нагрузочные эксперименты шаблон автоматически не запускает.

В CI параметр `check --tracked` также отклоняет файлы Git-индекса вне списка публичной поставки. Новый корневой файл или каталог нужно явно включить в allowlist; `.gitignore` не скрывает уже отслеживаемые файлы.

Архив содержит `PUBLICATION_MANIFEST.json` с SHA256 каждого исходного файла. UID/GID, имена владельцев и времена файлов нормализованы. Публикуйте чистый каталог, а не исходную рабочую Git-папку. Выберите имя репозитория самостоятельно; в поставку не добавлены выдуманные GitHub-ссылки или личный security-email.

## Перед открытием репозитория

Проверьте Git-имя/email автора новых коммитов, включите нужные настройки GitHub, в том числе Private vulnerability reporting, и выберите права участников. GitHub-аккаунт и метаданные новых коммитов не становятся анонимными от удаления секретов из исходников. При публикации готовых контейнеров дополнительно проверяйте их состав, лицензии и уязвимости; аудит Node-пакетов этого не покрывает.
